## What was tested

1. Match semiconductor **company aliases** and **industry phrases** in `V2Organizations` with token-safe rules (so `intel` does not match `intelligence`).
2. In one partition-pruned BigQuery scan, count each theme in the seeded set and in the disjoint non-seed background.
3. Score every support-qualified theme (`min_support = 25`) with lift / odds ratio / CIs, route sparse tables to Fisher exact, and apply Benjamini–Hochberg over the **complete** family before any presentation limit.
4. Compute exact source/day/seed concentration for every candidate.
5. Classify themes with a deterministic rule set for human review only.
6. Refuse automatic promotion: the task does not edit `configs/gdelt_theme_bundles.yaml`.

## Scientific verdict

**Rejected as a primary semiconductor identity layer.**

Many themes were statistically enriched around semiconductor organizations (manufacturing, servers, storage, inflation, currencies, monetary policy). None behaved as a reliable semiconductor *identity* label under the current deterministic rules (`industry_core = 0`). The production `semiconductors` theme bundle therefore remained empty.

Bounded conclusion for this window and corpus:

> Semiconductor relevance should be established through entity resolution and text-based classification. GDELT themes may remain useful as contextual features, not as the primary identity layer.

## How to reproduce (costs money)

Configs use `project_id: "YOUR_PROJECT_ID"`. Put the real project id in ignored `configs/local.yaml`. Always dry-run first.

```bash
kinetic run configs/research/semiconductors_seeded_theme_scoring_30d_dryrun.yaml
# review estimate, then:
kinetic run configs/research/semiconductors_seeded_theme_scoring_30d_execute.yaml
```

Live execution requires BigQuery credentials and the typed `execute_query: "ENABLE"` gate. The client still dry-runs first and enforces `maximum_bytes_billed` plus `configs/cost_policy.yaml`.

## Limits (read these)

- GKG records are not unique articles; syndication and multi-label themes inflate counts.
- The corpus is organization-seeded and NVIDIA-heavy in this window.
- Statistical significance is not semiconductor identity and is not a trading signal.
- No predictive-return study is claimed here.
- Absence of `industry_core` in this family does not prove no semiconductor theme exists outside the window, support threshold, or rule set.
